정리본이 본진이고, 문제는 두 가지 방식으로 푼다

앱을 켜면 문제부터 푸는 게 아니라 정리본을 읽는다. 문제는 정리본 단원 끝에서 기다리다가, 들어가면 연습이냐 실전이냐를 먼저 묻는다.

오른쪽 위 버튼으로 아래 모든 앱 화면의 라이트·다크가 바뀐다. 눌러보고 판단해줘 — 이 시안 페이지 자체의 색은 네 시스템 테마를 그대로 따라가니까 따로 신경 안 써도 된다.

2.3 비교 기반 정렬의 하한

원소를 오직 비교로만 판단하는 정렬은, 어떤 알고리즘이든 최악의 경우 Ω(n log n)번의 비교가 필요하다. n개 원소의 가능한 순열이 n!가지이고 비교 한 번이 경우의 수를 최대 절반으로만 줄이므로, 결정 트리의 높이가 최소 log₂(n!) ≈ n log n이 되기 때문이다.

따라서 병합 정렬 · 힙 정렬 · 팀 정렬은 이 하한을 달성하는 점근적으로 최적인 알고리즘이다. 삽입 정렬은 평균 O(n²)이지만, 거의 정렬된 입력에서는 O(n)에 가깝게 동작해 팀 정렬의 내부 루틴으로 쓰인다.

알고리즘최선평균최악추가 공간안정성
병합 정렬n log nn log nn log nO(n)안정
퀵 정렬n log nn log nn²O(log n)불안정
힙 정렬n log nn log nn log nO(1)불안정
삽입 정렬nn²n²O(1)안정
팀 정렬nn log nn log nO(n)안정

시험에 나오는 지점

  • 퀵 정렬은 평균만 n log n이고 최악은 n². 이미 정렬된 배열에서 첫 원소를 피벗으로 잡으면 최악이 터진다.
  • 삽입 정렬의 최선 O(n)과 평균 O(n²)을 같이 묻는 문제가 잦다.
  • 안정성을 묻는 문제에서 힙 정렬이 함정으로 자주 나온다 — 불안정하다.

3. 다음 정렬 알고리즘 중 평균 시간복잡도가 O(n log n)이 아닌 것은? [3점]
①병합 정렬 Merge Sort
②퀵 정렬 Quick Sort
③힙 정렬 Heap Sort
④삽입 정렬 Insertion Sort정답
⑤팀 정렬 Tim Sort내가 고른 답
정답 ④ 삽입 정렬 내가 고른 답 ⑤ 팀 정렬

삽입 정렬은 평균과 최악이 모두 O(n²)이다. 최선(이미 정렬된 입력)에서만 O(n)이 되는데, 이 최선값을 평균으로 착각하기 쉽다.

  • ① 병합 정렬 — 입력과 무관하게 항상 n log n. 분할이 균등해서다.
  • ② 퀵 정렬 — 평균은 n log n. 최악만 n²이라 이 문제의 답이 아니다.
  • ③ 힙 정렬 — 항상 n log n. 불안정하지만 복잡도는 안정적이다.
  • ⑤ 팀 정렬 — 삽입 정렬을 안에서 쓸 뿐 병합과 결합해 평균 n log n이다.
자주 걸리는 함정 · ⑤를 고른 사람 대부분은 “팀 정렬 안에 삽입 정렬이 있으니 같은 복잡도”라고 본다. 실제로는 짧은 구간에만 삽입 정렬을 쓰고 전체는 병합으로 합친다.

정리본 §2.3

병합 정렬 · 힙 정렬 · 팀 정렬은 이 하한을 달성하는 점근적으로 최적인 알고리즘이다. 삽입 정렬은 평균 O(n²)이지만, 거의 정렬된 입력에서는 O(n)에 가깝게 동작해 팀 정렬의 내부 루틴으로 쓰인다.
